# Core — Onboarding

## Job
"Tell it what kind of place this is, so it arrives with the right things already turned on."

## Whose job
The administrator of a brand-new organization, exactly once. Anyone else who lands here can only be
told who to ask — and told it in their own language, which is the first thing this area gets wrong
if the language is settled after the choice rather than before it.

## Inside the boundary
Choosing a workspace mode, setting the organization's name, country, currency and time zone (and,
if the founder accepts it, the country's document preset), and applying what
follows from the mode: its starter set of modules and their settings, its categories, storage types
and units, its starting locations (at least one ordinary place wherever the mode declares none),
and, where the mode runs the warehouse, the document preset and the quarantine shelf it names.

The mode **decides** that set; it does not add to one. This is the whole content of the question,
so a union is not an answer to it: onboarding used to append the mode's modules to a list the
organization already carried from the ORM's column default, and that default — eight hand-written
names — won every disagreement because it went first. A household choosing "Food & Home" was
handed the document register, with numbering, accounting periods and approval thresholds, which
its mode does not list and is not meant to.

What an organization holds before it has answered is therefore the always-on set and nothing else:
exactly what is not a choice. That is also what an account keeps if it creates an organization at
registration and never reaches this screen — a usable inventory, with no opinion attached. The one
addition onboarding keeps is a module the administrator switched on by hand while the question
stood open: an explicit decision the mode never asked about.

## Outside the boundary
- Creating stock. The categories, units and places it seeds are the **shape** of the workspace;
  no product, record or quantity is created.
- Configuring individual modules — that is Settings, and each module's own screens, afterwards.

## Own concepts / Borrowed
**Own:** nothing. It writes the mode, currency, time zone and module set into Organization, seeds
the rest through the areas that own it, and then gets out of the way.
**Borrowed:** the workspace modes and the module catalog.

## Deliberately not done
- **No sample data.** A workspace that starts with invented records cannot be told apart from one
  somebody has already begun using.
- **No import.** Bringing existing stock in is a job for the modules that own that stock.
- **No repeat.** The mode is changeable later in Settings; onboarding is not a screen anybody
  returns to.

## Switched off
Cannot be, but it disappears the moment the organization has a mode. If it reappears for a
workspace already in use, that is a defect, not a prompt.
